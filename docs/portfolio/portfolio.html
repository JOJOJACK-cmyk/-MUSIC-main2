OVERVIEW프로젝트 개요

음악은 혼자 듣기도 하지만, 누군가의 방송에서 함께 듣기도 합니다. 그런데 두 경험은 보통 서로 다른 서비스에 흩어져 있습니다. StreamWave는 음악 스트리밍과 라이브 방송을 하나로 묶어 “듣고 → 함께 듣고 → 응원하고 소장하는” 흐름을 한 곳에서 끝냅니다. 이용권·후원·스토어 결제와 환불, 채팅 관리, 관리자 기능까지 실제 운영을 전제로 만들었습니다.

PROBLEM SOLVING기술적 도전과 해결

돈과 실시간 방송이 오가는 서비스라, 기능을 “동작하게” 만든 뒤에 악용과 장애 상황을 먼저 찾아 막았습니다.

01라이브 방송 가로채기 방지

문제
스트림 키가 곧 HLS 파일 이름이라, 시청자가 주소에서 키를 보고 같은 키로 송출해 남의 방송을 가로챌 수 있었음. SRS 웹훅도 외부에서 호출 가능
해결
공개 playbackId와 비밀 streamKey를 분리 (OBS 키 = {playbackId}?key={streamKey}). on_publish 훅에서 키를 상수 시간 비교로 검증해 틀리면 송출 거부, 웹훅 경로는 Caddy 에서 외부 차단
결과
시청자에게 보이는 주소로는 송출 불가 · 외부에서 방송 강제 종료 불가

02결제 금액 위변조 · 재고 정합성

문제
이용권·음표·스토어 모두 클라이언트가 보낸 금액을 믿으면 조작 가능. 동시에 결제하면 재고보다 많이 팔릴 수 있음
해결
결제 전에 서버가 금액을 고정한 PENDING 주문 생성 → 승인 요청 금액이 다르면 토스를 부르지 않음. stock = stock - :qty WHERE stock >= :qty 로 원자적 차감 후 승인, 실패 시 트랜잭션 롤백
결과
금액 조작·중복 승인·초과 판매 차단, 환불 시 재고 복구 — 테스트로 검증

03실시간 채팅의 신원과 1인 1표

문제
클라이언트가 보낸 발신자 이름을 그대로 써서, 방송자 닉네임으로 투표창 명령을 보내거나 이름을 바꿔 무제한 투표 가능
해결
웹소켓 핸드셰이크에서 인증된 STOMP Principal로 발신자를 서버가 결정. 투표는 사용자 PK 기준 Redis SETNX, 음표 알림 같은 시스템 메시지 타입은 서버만 발송. 연결당 도배 제한
결과
사칭·중복 투표 차단 · 방송자 채팅 관리(삭제·채팅 금지) 기반 마련

04YouTube API 하루 할당량

문제
search.list는 호출당 100유닛(하루 약 100회). 비로그인 사용자가 검색어를 바꿔가며 할당량을 소진할 수 있었음
해결
동기화는 1유닛짜리 playlistItems·videos 위주로. 키 여러 개를 두고 할당량 사유의 403/429일 때만 봉인 후 다음 키로. 검색 보강은 로그인 사용자만, 사이트 전체 시간당 10회·하루 40회 상한
결과
검색 남용으로 동기화·관리자 등록이 막히는 상황 방지
StreamWave · 포트폴리오6

05“실시간” 차트를 진짜 실시간으로

문제
Redis 점수가 줄지 않는 누적값이라 한번 오른 곡이 계속 상위에 남았고, 같은 곡 반복 재생으로 순위 조작 가능
해결
시간대별 버킷(chart:h:{epochHour})에 쌓고 조회 시 최근 24개를 합산(30초 캐시). 같은 사용자·곡은 한 시간에 1점
결과
최근 24시간 청취가 그대로 반영되는 차트 · 반복 재생 조작 차단

06소셜 로그인 계정 탈취

문제
이메일로 기존 계정에 연결하는데 카카오는 미인증 이메일을 줄 수 있음. 회원가입에 이메일 인증이 없어 남이 먼저 내 이메일로 가입해 둘 수도 있음
해결
제공자가 인증한 이메일만 허용(is_email_verified, email_verified). 같은 이메일의 일반 계정에 처음 연결될 때 기존 비밀번호 무효화. 토큰은 URL 쿼리 대신 프래그먼트(#)로 전달
결과
미인증 이메일·사전 가입을 통한 계정 탈취 차단 — 회귀 테스트로 고정

07곡 삭제 FK 오류로 목록 전체가 실패

문제
비음악 영상을 목록 조회 중에 정리하는데, 좋아요·청취기록이 걸린 곡을 지우면 커밋 시점에 FK 오류 → 홈 화면 곡 목록 요청 전체가 500
해결
재현 테스트로 원인 확인 후 모든 삭제 경로를 MusicRemover로 통일(참조 기록 먼저 정리). 새 테이블은 ON DELETE CASCADE / SET NULL로 설계
결과
정리 대상 곡이 있어도 목록 조회 정상 · 플레이리스트·상품 연결도 자동 정리

08라이브 화면 레이아웃 · 모바일

문제
페이지 래퍼에 폭이 없어 내용 폭(약 760px)으로 줄어들어 영상 400px, 채팅은 메시지 한 줄. 새 채팅마다 페이지 전체가 스크롤. 휴대폰에서는 고정 사이드바 때문에 영상이 78px
해결
래퍼 폭 지정 · 채팅 최소 높이 · 투표창 45% 상한, 채팅 목록만 스크롤. 768px 이하에서 사이드바를 ☰ 서랍 메뉴로, 플레이어 바·헤더 압축
결과
1440px 기준 영상 400px → 772px · 390px 휴대폰에서 가로 넘침 없음 (브라우저로 실측)

QUALITY테스트 · 검증

결제·권한·실시간 기능은 실제 MySQL·Redis 를 붙인 통합 테스트로, 외부 결제는 Mockito 로 대체해 검증합니다. 화면은 실제 브라우저로 띄워 측정·촬영했습니다.

결제 · 주문음표 주문·승인 금액 위변조 거절, 중복 승인 1회 처리 · 스토어 재고 차감·환불·상태 전이 · 이용권 만료 알림 대상 선정
권한 · 보안남의 주문·플레이리스트 접근 거부 · 소셜 계정 연결 규칙(비밀번호 무효화, 닉네임 중복) · 카카오 미인증 이메일 · Rate Limit
실시간투표 1인 1표 · 투표 옵션과 카탈로그 곡 연결 · 채팅 금지 TTL · 차트 시간당 1점
회귀좋아요가 걸린 정리 대상 곡이 있어도 곡 목록 조회 성공 (실제 재현했던 FK 오류)
화면Playwright + Edge 로 1440 / 1024 / 768 / 390px 에서 레이아웃 실측, 시연 영상·스크린샷 자동 생성 (docs/demo)
